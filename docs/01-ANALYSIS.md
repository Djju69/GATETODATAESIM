# GATETODATA eSIM — Анализ проекта и поставщика

Дата анализа: 25.11.2026

## 1. Рынок и позиционирование

- Продукт: международный магазин туристических eSIM (реселлинг), бренд GATETODATA.
- Целевые аудитории: РФ/СНГ, Европа, Азия, США, международные путешественники.
- Ключевой инсайт: покупатель eSIM находится в «тревожном» контексте (поездка завтра/уже в пути), поэтому критичны:
  - скорость до покупки (1 экран → страна → тариф → оплата),
  - мгновенная выдача QR/LPA-кода,
  - работа из Telegram (аудитория РФ живёт в мессенджере),
  - понятная совместимость устройств до оплаты (снижает возвраты).

## 2. Поставщик TELMO eSIM — что выяснено

Источники: telmoesim.com/en/reseller, developer.telmoesim.com (v2.1), блог TELMO.

### Подтверждено (бизнес-модель)
- Реселлер работает с **предоплаченным кошельком (prepaid wallet)**: себестоимость пакета списывается с баланса при заказе.
- **Розничную цену назначает реселлер сам** — это наша маржа до платёжных комиссий.
- Программа: тарифы Starter / Professional / Enterprise (white label — с Professional).
- API + sandbox входят в программу; документация на developer.telmoesim.com.
- 200+ стран и регионов, одно-страновые, региональные и глобальные пакеты.
- Заказ через API возвращает QR, manual code (LPA), activation URL.
- Rate limit API: 100 req/min (базовый).
- Webhooks: заказы, активация, usage-пороги, истечение (по документации).
- Статусы заказа: pending / active / expired / failed.

### Критическая находка: документация API — PLACELHOLDER
На страницах developer.telmoesim.com (Endpoints Overview, Quick Start, Webhook Events) стоит явное предупреждение:

> «⚠️ Placeholder Documentation. These are placeholder endpoints. Real TELMO API endpoints, request/response formats, and parameters will be updated when you provide the actual API specifications.»

**Выводы:**
1. Публичные endpoint-ы (`GET /v1/packages`, `POST /v1/orders`, …) с высокой вероятностью НЕ финальные. Реальные нужно сверить по:
   - API Explorer на портале (нужен логин),
   - OpenAPI/спецификации в личном кабинете,
   - или письменному подтверждению TELMO-поддержки.
2. В коде это решается **адаптером поставщика** (Provider Adapter): весь магазин зависит от интерфейса `EsimProvider`, TELMO-адаптер — единственное место, где живут конкретные URL/форматы. Сверка с реальным API выполняется скриптом-пробой (`scripts/telmo-probe.ts`) по вашему API-ключу.
3. Нельзя считать, что рекламная кампания TELMO ($1, 100 использований, min $5, первый заказ) доступна через API. Статус: **не подтверждён**. Вопрос TELMO-поддержке: «Применяется ли моя кампания к заказам, создаваемым через API, и есть ли параметр промокода в API?»
   - До ответа: скидки реализуем **на нашей стороне** (наши промокоды уменьшают нашу розничную цену), а кампанию TELMO трактуем как вопрос к себестоимости.

### Неизвестные (запросить у TELMO, до ответа — не блокируем разработку)
1. Точные endpoint'ы, форматы запросов/ответов (нужен доступ к API Explorer / спецификация).
2. Способ пополнения кошелька и доступные методы.
3. Применяются ли кампании/купоны TELMO к API-заказам.
4. Есть ли webhooks у реального аккаунта и их подписи (секрет).
5. Что происходит со списанием кошелька при refund.
6. Ограничения реселлера: минимальная розничная цена, гео-ограничения продаж.
7. Параметры активации: начисляется ли срок с момента заказа или активации.

## 3. Оплата — варианты для старта (физлицо, РФ)

Правило: **eSIM выдаётся только после подтверждённого платежа.**

| Канал | Способ на старте | Комментарий |
|---|---|---|
| Telegram (бот/Mini App) | **Telegram Stars (XTR)** | Цифровые товары в ботах/Mini App по правилам Telegram оплачиваются Stars. Выплата через Fragment ~$0.013/Star. Работает без юрлица. |
| Сайт (физлицо, РФ) | **Криптовалюта USDT (TRC-20/TON)** | С 01.09.2026 расчёты с нерезидентами в криптовалюте разрешены (№ 418-ФЗ и изменения). Принимаем на свой кошелёк, авто-подтверждение по сети (TronGrid/TON API, бесплатные лимиты) — без посредников и их комиссий. |
| Сайт (когда будет ИП/ООО) | ЮKassa / CloudPayments / Robokassa | Карточки РФ и международные. Архитектура закладывает интерфейс `PaymentProvider` — подключается без переделки. |
| Международные карты (Stripe и т.п.) | Только с юрлицом и в поддерживаемой юрисдикции | На старте недоступно — не планируем. |

Крипто-приём проектируем как: инвойс с адресом и точной суммой → фоновая проверка транзакций (amount + memo/tag) → идемпотентное подтверждение заказа → выдача eSIM. Секреты (ключи) — только в env.

## 4. Telegram: бот против Mini App

**Решение: гибрид, но порядок важен.**

1. **Этап 1 — полностью нативный бот** (inline keyboards, редактирование сообщений):
   - ноль дополнительного хостинга, работает на слабых устройствах и в Desktop,
   - покрывает весь сценарий покупки, заказы, eSIM, поддержку.
2. **Этап 2 — Telegram Mini App на базе уже готового адаптивного сайта** (тот же Next.js-код, отдельный entry/режим):
   - каталог/корзина/checkout в веб-вью выигрывают у инлайн-клавиатуры по UX,
   - бот остаётся каналом уведомлений и быстрых действий,
   - дополнительные затраты минимальны (один код, один хостинг).
3. Авторизация: Telegram Login Widget / initData → единый аккаунт на сайте и в боте (смежность по telegram_id), магический email-линк для входа без пароля.

## 5. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| Документация TELMO — placeholder | Интеграция «вслепую» | Адаптер + probe-скрипт + сверка с поддержкой до запуска продаж |
| Нет юрлица → нет карточного эквайринга | Потеря конверсии у части РФ-клиентов | Stars + USDT на старте; карточки — при открытии ИП/ООО (провайдер подключается в тот же интерфейс) |
| Ручное пополнение кошелька TELMO | Заказы падают при нулевом балансе | Мониторинг баланса (probe), уведомление в админку и Telegram админу при пороге |
| Возвраты/претензии | Юр. ответственность на физлице | Понятные условия до оплаты, статусы заказов, лог действий, поддержка |
| Двойная выдача/двойная оплата | Деньги/деньги | Идемпотентность webhook-ов, state machine заказа, уникальные ключи провайдера |

## 6. Что делаем с неизвестным

Все неизвестные TELMO из п.2 сформированы в конкретный вопрос-лист (см. `docs/06-QUESTIONS.md`). Разработку они не блокируют: адаптер и вся воронка строятся против интерфейса, сверка — один скрипт.
